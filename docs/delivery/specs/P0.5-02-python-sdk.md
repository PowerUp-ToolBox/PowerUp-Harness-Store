## Problem Statement

With P0.5-01 a Python program can run as a Harness, but the author still has to read the launch environment variables by hand, construct an OpenAI client pointed at the Model Gateway, know the Slot naming rules, and parse the Gateway's error format to tell a `slot_unbound` from a real failure. Node authors already get this from `@harness-store/sdk`; Python authors are left copying snippets from the docs, and each copy drifts.

## Solution

Publish a `harness-store` package on PyPI that mirrors the Node SDK: read the launch context, hand back a ready-to-use OpenAI-compatible client (sync and async), expose Slot helpers, and translate Gateway errors into typed exceptions. It is a thin convenience layer over the documented protocol, never a requirement: a Harness that ignores it and speaks HTTP to the Gateway is equally valid.

## User Stories

1. As a Publisher writing Python, I want to `pip install harness-store` and get a client in two lines, so that I can spend my time on the agent, not plumbing.
2. As a Publisher, I want `get_context()` to return the Harness ID, version, locale, Data Directory, Workspace (if any), platform and declared Slots, so that I never parse environment variables myself.
3. As a Publisher, I want `create_openai_client()` and `create_async_openai_client()` that are pre-configured with the Gateway URL and Gateway Token, so that the standard `openai` package works unchanged.
4. As a Publisher, I want to pass a Slot name as the `model` argument and have it just work, so that my Harness never hard-codes a vendor model.
5. As a Publisher, I want a `Slots` helper that exposes my declared Slot names as constants read from the Manifest at runtime, so that a typo fails fast.
6. As a Publisher, I want a `SlotUnboundError` raised when the User has not bound a Slot, with the Slot name and the User-facing message, so that I can show helpful UI instead of a stack trace.
7. As a Publisher, I want `ProviderError` and `GatewayError` exceptions carrying the Gateway's error code and any provider status/message, so that I can distinguish "User must fix a binding" from "the upstream model failed".
8. As a Publisher, I want `resolve_slot(slot)` to tell me which real `provider/model` will answer, so that I can display it in my UI.
9. As a Publisher, I want `get_port()` for web UI Kind Harnesses, so that my FastAPI/Flask app binds to the right port.
10. As a Publisher, I want the SDK to work under Python 3.11 through 3.13 with no dependencies other than `openai` and `httpx`, so that it never conflicts with my own dependency tree.
11. As a Publisher, I want the SDK to fail with a clear message when run outside the Runtime (variables missing), so that local development mistakes are obvious.
12. As a Publisher, I want a documented "run locally without the Runtime" mode where I can point the SDK at any OpenAI-compatible endpoint via explicit arguments, so that I can develop before installing.
13. As a Publisher, I want type hints and docstrings on every public function, so that my editor guides me.
14. As a Publisher, I want a minimal example project (terminal UI Kind) and one web example (FastAPI) in the repository, so that I can copy a working starting point.
15. As a User, I want Python Harnesses built with the SDK to respect my Slot Bindings and Model Overrides identically to Node Harnesses, so that the platform behaves consistently.
16. As a platform developer, I want the Node and Python SDKs to share one behavioural conformance test list, so that they cannot drift.

## Implementation Decisions

- Package name `harness-store` on PyPI; module `harness_store`. Semantic versioning independent of the app; the major version tracks the Gateway protocol major.
- Public surface (mirrors P0-06's Node SDK): `get_context()`, `create_openai_client(**overrides)`, `create_async_openai_client(**overrides)`, `Slots` (dynamic attribute access over declared Slot names, sourced from the Gateway's harness context endpoint, cached for the process lifetime), `resolve_slot(slot)`, `get_port()`, exceptions `HarnessStoreError` → `NotInRuntimeError`, `GatewayError` → `SlotUnboundError`, `UnknownSlotError`, `ProviderNotConnectedError`, `ProviderError`, `ProviderTimeoutError`, `InvalidTokenError`.
- Error translation wraps the `openai` package's `APIStatusError`: the SDK inspects the Gateway's `error.code` and re-raises the typed exception, preserving the original as `__cause__`.
- Local development mode: `create_openai_client(base_url=..., api_key=...)` bypasses environment discovery; `get_context()` in that mode returns a context with `in_runtime = False` and empty Slots rather than raising, so the same code path runs in both places.
- Dependencies: `openai>=1`, `httpx`; nothing else. No Pydantic requirement beyond what `openai` brings.
- Distribution: built and published from the monorepo by CI on tag; the examples in the repository depend on the local path during development and the PyPI version in their published Manifest.
- Documentation lives beside the Node SDK's authoring guide (R-0603) as a Python tab, not a separate document.

## Testing Decisions

- Tests assert behaviour visible to a Harness author: correct base URL and token on the created client, correct exception type per Gateway error code, correct context fields from a scripted environment.
- Primary seam: **Gateway HTTP seam** (architecture §8, item 1). Run the real `packages/gateway` server in-process with the fake Provider and exercise the Python SDK against it in a subprocess; this proves protocol compatibility rather than mocking it.
- A shared conformance list (markdown table in the repository) enumerates scenarios both SDKs must pass; each SDK's test suite references the scenario ids.
- Prior art: the Node SDK tests from P0-06.

## Out of Scope

- Framework integrations (LangChain, LlamaIndex adapters).
- Streaming helpers beyond what the `openai` package already provides.
- Anthropic-format client helpers (arrives with P1-03).
- Any agent loop or tool framework; the SDK is transport only.

## Further Notes

Keep the SDK small enough that a Publisher could read it in ten minutes. Its value is trust and consistency, not features.
